# Aerial Top Shelf 主功能规范与多账号实验提案

版本：3.0，2026-11-12。替代 v2 的设计与示例代码。实现分支：`feature/top-shelf`。

## 1. 范围与验收状态

本轮交付 P1（数据和本地内容管理）、P2（视觉和焦点交互），提供独立测试 Release。P3 为真机验收，必须记录原始输出和未通过项；编译、单测和截图不能替代真机验收。P4 多账号与自动选人仅为实验提案，不属于本轮主功能。

Top Shelf 读取来源应用向系统发布、当前 Android 用户可见的数据。不能保证应用一定发布数据，也不能获取其完整历史。内容链接由来源应用控制；正确打开内容、直接续播、要求登录／选用户应分别记录。

## 2. 安装隔离：本轮最高优先级

- 测试 applicationId：`app.orchard.tv.topshelf`。Kotlin namespace 保持 `app.orchard.tv`；Activity 完整名为 `app.orchard.tv.MainActivity`。
- 测试包不声明标准或厂商 HOME 类别，不进入默认桌面候选；standard 和 guard 测试构建均为手动启动的普通应用。
- 测试构建禁用 BootReceiver、ConfigReceiver、HomeGuardService、RevivalListener、RevivalSyncService、RevivalAccountService 和系统 DreamService。
- 不申请 WRITE_SECURE_SETTINGS、系统悬浮窗、系统设置写入、开机广播等接管权限，不自动启动守护、开机应用、复活或系统屏保设置。
- 不覆盖正式安装，不复制其私有设置、照片和图标数据，不更改正式版的默认桌面、无障碍服务、开机启动与屏保配置。
- 手机设置端口：测试版 8791，正式版仍为 8790。
- 禁止对测试 APK 使用 `tools/install.sh`。只用 `tools/install-topshelf-test.sh` 或直接 ADB 安装并手动启动。
- 安装器先核对测试包名；CI 在发布前核对合并 Manifest 中无 HOME、接管组件禁用和接管权限移除。安装前后读取并比较 HOME 解析结果与完整无障碍列表，不改写这些值。
- 若现有正式桌面守护阻止打开测试版，停止该项验收并记录原因；不关闭、改写或重配正式版守护。
- 卸载只卸载测试包。不得停用或卸载正式版或系统桌面。

## 3. P1：数据与内容管理

### 3.1 数据模型与查询

使用现有 `topshelf/` 目录，保持查询、偏好、图片缓存与 UI 分离，不引入新的电视 SDK。

- Android 8.0+ 且 TvProvider 存在时才启用查询；低版本、未授权和不可用情况保留原桌面。
- 使用 READ_TV_LISTINGS 运行时授权。所有普通调用者查询的 selection 为 null；查询后在内存中处理数据。
- Watch Next 与 Preview Programs 分别查询、分别容错；推荐节目关联频道显示名称。旧厂商缺少可选列时退回基础 projection。
- 读取明确的节目级 browsable=0 时不展示；频道 browsable 与节目状态不混为一谈。
- 模型包括包名、来源类型、Provider 行 ID、content/internal ID、内容链接、标题、封面、Watch Next 类型、季集、集标题、简介、播放位置、时长、最近交互时间、频道名和推荐权重。
- Watch Next 类型区分继续观看、下一集、新一集、待看，不一律标注为未看完。
- 先按 Watch Next／推荐，再按最近交互时间或推荐权重排序；按包名和内容链接去重，每类最多 20 条，总计最多 40 条。
- 本地隐藏使用包名、来源与稳定内容标识的哈希；无稳定标识时退回内容链接。Provider 行 ID 不作为唯一持久身份。
- 进度保持真实 0–100%，不人为截断到 3–98%。字段缺失时不编造进度或剩余时间。

### 3.2 刷新与导航稳定性

首页在前台时监听 Watch Next、Preview 和 Channel 变更，合并短时间重复事件；离开前台取消读取与监听，返回时刷新。短暂后台切换可保留内存数据以避免闪屏，撤销权限或关闭功能时清空可展示数据。

焦点应用使用 180ms 防抖；当前显示来源与待切换来源分开。过渡旧内容不可点击、不可接收焦点，不得把上个应用的链接当作当前应用内容打开。Provider 刷新优先按条目 ID 保持当前选择，条目消失时选择有效邻居／首条，全空则回来源磁贴。

### 3.3 本地管理

卡片菜单由长按 OK 或菜单键打开，操作包括播放、在 Aerial 中隐藏、关闭此应用顶部预览。选择后才执行，不用长按直接删除。

隐藏和按应用关闭持久保存，重启后仍有效。个性化提供“恢复顶部内容”，明确恢复隐藏条目和所有按应用关闭的预览。

只改变 Aerial 的展示偏好，不修改来源应用的历史，不发送系统受保护的 BROWSABLE_DISABLED 广播，不伪造系统删除行为。

### 3.4 图片与资源预算

- 先展示文字和占位；图片失败不丢弃条目。只加载可见与邻近卡片，不串行等待所有应用的封面。
- 网络并发最多 2，单图下载最多 6MiB，连接／读取超时各 4 秒；连接和输入流必须关闭。
- 内存 LRU 12MiB，磁盘缓存 48MiB，图片 TTL 3 天；磁盘按修改时间淘汰，写入采用临时文件替换。
- 缓存键包含 URI、目标像素宽高和绘制版本。根据画布密度生成图片，不强制打开 4K UI。
- 后台采样、居中裁剪（人物可偏上）、底部暗角合成和连续圆角裁切；生成不可变位图。使用 `smoothCut` 已返回不可变位图时不重复复制。
- 低内存回调清理 Top Shelf 内存缓存；不得 recycle 仍可能被 UI 引用的位图。

## 4. P2：视觉与遥控器交互

### 4.1 内容结构与几何

采用一条混合轨道，继续观看在前、推荐在后；不保留阻挡上键路径的分类栏。分节标题显示来源应用与当前条目类型，下方统一显示当前条目的主标题和季集／剩余时间／频道信息。

按 960×540dp 画布设计。默认单排首页卡片高 110dp、宽约 196dp，间距 20dp、连续圆角 12dp，主图起点与应用磁贴 x=56dp 对齐。轨道在两端额外预留 20dp、上方 24dp、下方 40dp 供焦点放大、外框与阴影绘制。

单排以四张完整卡片为目标，不再同时要求第五张在安全区内露边。双排和名称布局按实际 GridMetrics 压缩卡片高度，不硬编码 Dock 的 y 坐标。元数据和焦点外框不得覆盖 Dock 或状态栏。

### 4.2 绘制与动效

- 无实时模糊、无空闲无限动画。静态封面、阴影与聚焦框按尺寸缓存；简单的进度条可即时绘制，不因进度更新重烘整幅封面。
- 复用现有 AppTile 的连续圆角阴影与玻璃聚焦框；聚焦缩放 1.09，高对比度外框间隙 4dp、线宽 2.5dp。
- 不可变图与装饰在后台准备；缺图时使用文字占位。角标与副标题使用资源文件，不写死中文。
- 防抖 180ms，展架入场位移 14dp，使用临界阻尼弹簧；支持的应用间做 240ms 内容溶解，避免容器反复收合。
- 大时钟淡出 220ms、淡回 260ms，使用 ModulateAlpha；展架显示时状态栏显示时间。
- 横向轨道使用临界阻尼弹簧（stiffness=320），重新定向时保留动画速度；首尾按键播放边界反馈并做轻微回弹／倾斜。
- “减少动画”时停止位移、回弹和缩放，内容可直接切换。完整静态壁纸与视频壁纸场景分别测量，不把整个桌面“0 帧”作为无条件断言。

### 4.3 焦点状态机

| 位置 | 操作 | 结果 |
| --- | --- | --- |
| 首排应用 | 左右 | 更新预览；180ms 内掠过不提交新来源 |
| 首排应用 | 确认 | 正常打开应用首页 |
| 首排应用且有内容 | 上 | 首次进入第一张；同次展示再次进入恢复上次卡片 |
| 首排应用且无内容 | 上 | 原有状态栏路径 |
| 卡片 | 左右 | 选择相邻条目并平滑滚动，首尾回弹 |
| 卡片 | 确认 | 打开来源应用提供的内容链接 |
| 卡片 | 上 | 直达状态栏 |
| 状态栏 | 下 | 有展架时回刚才卡片，否则回来源应用 |
| 卡片 | 下／返回 | 回触发展架的原应用磁贴，不能启动屏保 |
| 卡片 | 菜单／长按确认 | 打开卡片菜单；结束长按的抬键不得触发菜单第一项 |

跨层方向键的剩余 repeat／up 必须消耗，不能一按跨过多个焦点层。所有可按控件复用 Pressable。进入控制中心、移动模式、文件夹、儿童／长辈模式、锁定或屏保时，按既有规则暂停或隐藏展架，不窃取浮层焦点。

### 4.4 深链

解析 intent URI，校验显式包名与组件属于发布者，清除 selector、ClipData 和不需要的授权标志，再从 Activity 打开。失败显示不可用提示；不把应用首页当作续播成功。保留当前实现的包名校验与异常处理。

## 5. P3：测试与真机验收

### 5.1 CI

两种版本运行完整 release 单测，再构建独立测试包并执行 lint。既有 lint 基线不新增豁免 NewApi 或本功能错误。检查包名、版本、合并 Manifest、签名、APK／DM 校验和，成功后发布独立 prerelease，不能成为 Latest 正式版。

测试覆盖查询兼容性、节目状态、类型与元数据、本地偏好重启保持、稳定隐藏键、图片缓存与解码预算、遥控器进出轨道和状态栏、长按不误触、数据删除／重排、无权限和低版本降级。

### 5.2 真机流程

1. 使用已确认的设备连接读取原始状态，记录 HOME 解析结果、完整无障碍列表、screensaver_components、dreams_enabled，以及正式包版本／签名／可用开机设置。只读，不修改。
2. 使用隔离安装器装测试 APK（Android 9–11 选 api28.dm，12+ 选 api31.dm，与 APK 同名安装），只授予测试包 READ_TV_LISTINGS，手动打开测试 Activity。
3. 在确认实际发布可见内容的应用中播放后返回测试版；逐项记录数据、封面、进度、深链落点，不能按应用名称承诺支持。
4. 验证所有遥控器路径、长按、重排／删除、快速换应用、断网、撤权、低内存和重新打开后的缓存恢复。区分缓存命中与冷启动，不承诺网络封面 0.2 秒内下载完成。
5. 分别用静态／视频壁纸运行 perf.py；记录刷新率、P50/P90/P99、掉帧和内存。60Hz 的预算约16.7ms，120Hz约8.3ms；与同机原桌面基础场景作增量比较，P90≤18ms不能作为120fps达标证明。
6. 按 HOME，读取焦点和 HOME 解析结果，应回到既有正常桌面。比对上述原始状态全部保持；不为测试做默认桌面切换或开启测试守护。
7. 若执行环境无法路由到电视，或调试未授权，记录具体阻塞，停留在“待真机验收”，不得声明安装成功或验收通过。

## 6. P4：多账号实验提案（未实现）

### 6.1 手动命名快照

仅在用户明确保存时创建应用内容快照，并显示名称、保存时间和过期状态。允许查看、刷新和删除自己的快照。它只是旧数据的展示副本，不表示当前应用正在使用该 Profile，也不保证进度、授权或深链仍有效。

不采用“内容重合度超过50%即可识别账号”。标准公开条目不能作为跨应用通用的服务内 Profile 身份依据；Netflix、Disney+ 的发布与切换行为必须按设备和版本验证。

### 6.2 自动选人与 PIN：先验证再立项

现有守护声明 canRetrieveWindowContent=false；FLAG_REPORT_VIEW_IDS 不会授予读取能力。修改无障碍内容能力涉及独立的权限和隐私设计，不能作为“临时开一个 flag”的主功能改动。

普通应用执行 `sh -c input keyevent` 不会取得 ADB shell 权限，不能作为通用跨应用注入兜底，也不在本项目加入常驻 adbd 通道。先验证目标应用版本的可操作节点与合法交互路径；失败保留手动选人／输入。

若将来实现，只能按应用显式选择开启、使用确认的页面和前台包名，设置短时任务令牌、逐步校验、超时和取消，不可靠固定延迟盲输。PIN 使用独立输入组件和受保护的凭据存储，不复用家长密码保存逻辑；不得进入日志、快照、备份或手机 API 回显。输入完成须有可验证结果，不能以已排队点击代表成功。

本章不承诺 Netflix／Disney+ 通用自动选人、自动解锁或两键直接续播。
